1. Visão geral do projeto

SDM Links é o portal oficial do canal Sneakers do Mio. É uma vitrine editorial de sneakers focada em três coisas: drops em primeira mão, ofertas com cupom e conteúdo editorial sobre cada modelo. O site converte o público do Telegram (265K), Instagram (186K) e TikTok (24.5K) em cliques de afiliado.

O que o site resolve

  • Para o visitante: encontrar rapidamente o tênis certo pelo preço certo, com cupom ativo e link direto da loja.
  • Para o admin (você): publicar posts, ofertas, cupons e banners de parceria sem precisar tocar em código ou subir deploy.
  • Para o negócio: rastrear cliques em cada CTA (data-track) e medir conversão via dashboard interno.

Princípios editoriais

  • Imagem real do produto (nunca placeholder).
  • Preço em BRL, com preço tabela riscado quando há desconto.
  • Cupom sempre visível no card quando existir.
  • Link de afiliado com UTM automático (utm_source=sdmlinks).

3. Área pública — o que o visitante vê

URL: https://sdm-links.onrender.com/ (ou domínio custom). A home é dividida em 9 blocos, todos alimentados pelo banco exceto categorias/filtros fixos.

3.1 Faixa de anúncio (opcional)

Barra no topo com texto em marquee + botões do Telegram/WhatsApp. Controlada em Admin → Configurações. Quando banner_active=false, a faixa some.

3.2 Hero (blobs animados)

Chamada principal "Achamos o tênis certo. Pelo preço certo." com 3 botões: Telegram, Instagram, TikTok. Conteúdo fixo no HTML.

3.3 Ticker de ofertas

Faixa inferior do hero em loop horizontal. Dinâmico via /api/offers — puxa as 6 primeiras ofertas ativas. Se não houver oferta, o ticker some.

3.4 Busca + filtros por marca

Barra de busca instantânea (/api/search) + 10 chips de filtro (Nike, Adidas, NB, Jordan, Lifestyle, Treino, Futebol, Skateboarding, Basquete, Favoritos). Favoritos usa localStorage.

3.5 Ofertas de hoje

Grid de até 3 colunas, dinâmico via /api/offers. Cada card mostra imagem, marca, preço tabela riscado, preço atual, cupom (se houver) e botão "Pegar oferta".

3.6 Banners de parceria

Seção escura full-width, dinâmica via /api/partnerships. Renderiza um banner por parceria ativa (ordenado por position).

3.7 Próximos lançamentos

Grid 2 colunas, dinâmico via /api/posts/upcoming. Filtra posts com release_date futuro e renderiza até 6 com imagem + marca + data.

3.8 Cupons ativos

Grid 4 colunas (2 no mobile), dinâmico via /api/coupons. Suporta 4 variantes visuais (primary/dark/accent/outline). Click copia o código ou abre URL externa (se configurada).

3.9 Feed editorial (posts)

Layout em 2 colunas: esquerda = post em destaque sticky, direita = timeline com scroll infinito. Dinâmico via /api/posts?limit=12&offset=X. Suporta filtro por marca/categoria.

3.10 CTA final + Footer

Chamada pro Telegram + rodapé com links institucionais.

4. Página do produto (post)

URL: /post/:slug. Renderizada a partir de public/post.html com meta tags injetadas via SSR (src/seo.js) para compartilhamento limpo no WhatsApp/Telegram.

Blocos

  • Hero — imagem principal, título, marca, modelo, preço.
  • Galeria — até 20 imagens extras (post_images).
  • Onde comprar — lista de lojas vinculadas (post_stores) com CTAs.
  • Me avise quando lançar — aparece só se o release_date for futuro. Ativa Web Push ou e-mail.
  • Relacionados — produtos da mesma marca (/api/posts/:slug/related).
  • Botão de like — incrementa posts.likes.
  • Compartilhar — botões para WhatsApp, Telegram, Twitter + copiar link.
  • Story Generator — gera imagem 9:16 pronta pra Instagram Story (canvas nativo).

5. Calendário de lançamentos

URL: /calendario. Lista todos os posts com release_date agrupados por "Hoje", "Esta semana", "Em breve" e "Passados". Usa /api/posts/upcoming com limite 60.

  • Cada card mostra imagem, contagem regressiva ao vivo e link para o post.
  • Ordenação: futuros primeiro (mais próximos no topo), depois passados.
  • Acessível pelo menu/footer via #lancamentos ou link direto /calendario.

6. Painel Admin — acesso e navegação

6.1 Login

URL: /admin/login. Credenciais são armazenadas hasheadas (bcrypt) na tabela admins. Ao autenticar, uma sessão é criada (express-session) e guardada num cookie. Expira em 24h.

Importante Se esqueceu a senha, é preciso resetar direto no banco rodando um script Node que faça bcrypt.hash(novaSenha, 10) e atualize admins.password. Não há fluxo de "esqueci minha senha".

6.2 Layout do painel

Após login você cai em /admin. A barra superior tem 5 abas:

AbaFunção
PostsCriar e gerenciar reviews editoriais de cada tênis.
OfertasGerenciar os cards de "Ofertas de hoje" na home.
CuponsGerenciar a seção "Usa agora, economiza hoje".
ParceriasGerenciar banners full-width (ex: hotsite Nike).
ConfiguraçõesControlar faixa de anúncio do topo + Google AdSense.

Cada aba tem um formulário à esquerda (criar/editar) e tabela à direita (listar/editar/excluir).

7. Admin · Posts (CRUD)

Posts são o conteúdo editorial principal. Cada post vira uma URL /post/:slug e aparece no feed da home.

7.1 Criar um post novo

Passo 1. Aba Posts → formulário à esquerda.
Passo 2. Preencha Título (obrigatório) e Categoria (obrigatório: Lifestyle, Basquete, Treino, etc).
Passo 3. Envie a imagem principal (hero) — arquivo do seu PC. Vai parar no Supabase Storage automaticamente.
Passo 4. Preencha os metadados: marca, modelo, SKU, colorway, preço atual, preço tabela e data de lançamento (se for drop futuro).
Passo 5. Galeria (opcional, até 20 imagens) — aparecem no carrossel da página do produto.
Passo 6. Onde comprar — selecione loja e cole URL. Repita para cada loja. Marque status (disponível agora, em breve, esgotado).
Passo 7. Relacionados (opcional) — produtos similares com nome, imagem e link.
Passo 8. Flags: Destaque (fixa no topo do feed) e Patrocinado (marca o card).
Passo 9. Clique em Publicar post. Redireciona pra página nova.

7.2 Editar um post

  1. Na tabela à direita, clique em Editar na linha desejada.
  2. O formulário carrega com os dados atuais.
  3. Mude o que precisar. A imagem hero só é substituída se você enviar uma nova.
  4. Clique em Salvar alterações.
Slug automático Se você mudar o título, o slug é recalculado (mantendo a unicidade). URLs antigas passam a redirecionar sozinhas.

7.3 Excluir

Clique em Excluir na linha. Confirma no prompt. Imagens no Storage não são apagadas (precisam ser limpas manualmente no Supabase se quiser poupar cota).

7.4 Boas práticas

  • Use imagens com fundo transparente ou branco e proporção quadrada ou 4:3.
  • release_date futuro = aparece em "Próximos lançamentos" e "Calendário".
  • price_cents em centavos: R$ 449,99 = 44999.
  • Tags separadas por vírgula (ex: nike,air max,retro) ajudam a busca.

8. Admin · Ofertas (CRUD)

Ofertas são cards curtos de promoção que aparecem em "Ofertas de hoje" na home. Diferente dos posts, não têm página própria — são só call-to-action direto pra loja.

8.1 Criar oferta

  1. Título — ex: "Air Force 1 Low 'Oil Green' · -44%".
  2. Marca (obrigatória) e Categoria (opcional).
  3. Imagem — obrigatória em ofertas novas. Sobe direto pro Supabase.
  4. Preço e Preço tabela — em reais com vírgula.
  5. Cupom (opcional) — mostra um chip amarelo no card.
  6. Badge (opcional, até 24 chars) — ex: "-44%", "Menor preço".
  7. URL afiliado — link de destino.
  8. Posição — ordem crescente (0 = primeiro).
  9. Ativa — desmarca para ocultar sem apagar.
  10. Clique em Publicar oferta.

8.2 Editar / excluir / alternar

  • Editar — carrega os dados. A imagem só troca se você enviar nova.
  • Toggle status — clique no badge "Ativa/Inativa" da tabela para alternar sem abrir o form.
  • Excluir — botão vermelho. Pede confirmação.
Dica As 6 primeiras ofertas ativas também alimentam o ticker do hero. Mantenha a posição ordenada para controlar a prioridade visual.

9. Admin · Cupons (CRUD)

Cupons são os 4 cards da seção "Usa agora, economiza hoje". Cada cupom pode copiar o código ao ser clicado (padrão) ou abrir uma URL externa (ex: canal secreto do Telegram).

9.1 Campos do formulário

CampoFunção
CódigoObrigatório. Sempre maiúsculo (ex: NIKE20).
Marca / rótuloTexto pequeno no topo do card (ex: "Nike", "New Balance").
Descrição do descontoLinha inferior do card (ex: "30% cashback", "20% OFF").
URL externaSe preenchida, o card vira link em vez de copiador. Use para cupom secreto do Telegram.
Estilo do card4 variantes: primary (azul), dark (cinza escuro), accent (amarelo), outline (borda).
PosiçãoOrdem de exibição (0 = primeiro).
AtivoDesmarca para ocultar.

9.2 Fluxos

Criar, editar, toggle e excluir funcionam igual ao das ofertas. Recomendado: manter 4 cupons ativos para o grid ficar visualmente balanceado.

UX do clique Quando o visitante clica no card sem URL, o código é copiado pro clipboard e um toast aparece. Quando tem URL, abre em nova aba com rel="noopener".

10. Admin · Parcerias (CRUD)

Parcerias são os banners escuros full-width que ficam entre "Ofertas" e "Próximos lançamentos". Servem para ações especiais (hotsite exclusivo, campanha com marca).

10.1 Campos

CampoFunção
TítuloObrigatório. Tipografia grande (ex: "Hotsite Nike × SDM").
BadgePill amarelo acima do título (ex: "Parceria oficial").
SubtítuloLinha de descrição (ex: "Produtos exclusivos com cupom").
DestaquePalavra em amarelo dentro do subtítulo (ex: "NIKE20").
Texto do botãoCTA (ex: "Acessar hotsite →").
URL do botãoLink de destino.
Posição / AtivaOrdem + on/off.

10.2 Dicas

  • Mantenha no máximo 2 parcerias ativas ao mesmo tempo para não poluir a home.
  • Use o campo Destaque para evidenciar o cupom ou desconto.
  • URL deve incluir UTM: ?utm_source=sdmlinks&utm_medium=site&utm_campaign=banner-X.

11. Admin · Configurações (banner + ads)

11.1 Faixa de anúncio (topo)

É aquela barra colorida que passa texto em loop no topo do site.

  1. Abra a aba Configurações.
  2. Ligue/desligue no toggle Faixa ativa.
  3. Texto — o que vai passar no loop (ex: "🔔 Receba drops em tempo real!").
  4. URL Telegram e URL WhatsApp — botões flutuantes na faixa.
  5. Cor de fundo — picker + input hex. Preview ao vivo no quadro à direita.
  6. Clique em Salvar configurações.
Cache A API /api/banner tem cache padrão do cliente (sem Cache-Control explícito). Alterações aparecem no próximo carregamento. Para forçar, hard reload (Ctrl+Shift+R).

11.2 Google AdSense (se habilitado)

Mesmo bloco de configurações permite ligar ou desligar a exibição de ads e setar:

  • ads_publisher_id — seu ID do AdSense.
  • ads_slot_feed, ads_slot_post, ads_slot_sidebar — os slots.

Quando ads_enabled=false, nenhum script do AdSense é carregado — útil em período de aprovação ou se quiser pausar.

12. Admin · Cliques e estatísticas

Todo botão importante no site tem um atributo data-track="<label>". Clicar dispara um POST em /api/track que grava uma linha em clicks.

12.1 O que você vê no dashboard (aba Posts)

  • Totais por período — 24h, 7d, 30d, histórico total.
  • Gráfico por dia — últimos 14 dias.
  • Top 50 labels — ranking dos CTAs mais clicados + timestamp da última ação.

12.2 Labels usados no site

LabelOrigem
hero-telegram / hero-instagram / hero-tiktokBotões do hero.
offer-clickBotão "Pegar oferta" em qualquer card.
coupon / coupon-inline / coupon-linkCards de cupom.
partnership-NCTA de um banner de parceria.
upcoming-click"Ver detalhes" dos cards de próximos lançamentos.
banner-hotsite-nikeLegado (pre-CRUD) — ainda pode aparecer.

12.3 Rate limit

O endpoint /api/track aceita 60 requests/min por IP. Evita flood sem bloquear uso legítimo.

13.1 Campos críticos de posts

  • slug — único, usado na URL.
  • image_url — hero principal. Sem ela, o card vira placeholder cinza.
  • release_date — se futuro, o post aparece em "Próximos lançamentos" e "Calendário".
  • is_pinned=1 — fixa o post no topo do feed.
  • likes — incrementado pelo botão na página do post.

15. Deploy e variáveis de ambiente

15.1 Fluxo de deploy

Push para main no GitHub → Render detecta → builda (npm install) → sobe o server (node server.js). Leva cerca de 1–2 min.

15.2 Variáveis necessárias

VariávelUso
DATABASE_URLConnection string do Supabase Postgres. Sem ela, cai no SQLite local.
SUPABASE_URLURL do projeto Supabase (usado pelo client JS).
SUPABASE_SERVICE_ROLE_KEYService key para upload de imagens no Storage.
SESSION_SECRETChave de assinatura dos cookies de sessão.
VAPID_PUBLIC_KEY / VAPID_PRIVATE_KEYOpcional. Ativa Web Push. Sem elas, "Me avise" só aceita e-mail.
VAPID_SUBJECTOpcional. Email de contato do VAPID (default: admin@sdmlinks.com.br).
CLARITY_IDOpcional. ID do Microsoft Clarity para heatmap.
Segurança Nunca commite .env. Nunca cole DATABASE_URL em chat/Slack. Se vazar, troque a senha no Supabase → Settings → Database → Reset password e atualize a env no Render.

15.3 Rodar localmente

npm install
# crie .env com SUPABASE_URL e SUPABASE_SERVICE_ROLE_KEY no mínimo
node server.js
# abre http://localhost:3000

16. Troubleshooting

16.1 "Erro ao carregar oferta" ao editar

Causa histórica: service worker cacheava respostas do /admin/*. Corrigido no commit 17c95c7 (SW agora ignora rotas admin). Se voltar a aparecer, limpe o SW: DevTools → Application → Service Workers → Unregister → hard reload.

16.2 Card sem imagem

Sempre que um post/oferta tem image_url = null, o frontend mostra um fallback cinza com texto. Solução: abra o item no admin e envie a imagem, ou cole uma URL pública (ex: StockX CDN) no campo image_url via SQL.

16.3 Deploy não atualiza

  • Confira no Render se o build está em "Live" (não "Building" ou "Failed").
  • Hard reload no browser (Ctrl+Shift+R) pra pular cache local + SW.
  • Se ainda falhar: DevTools → Application → Storage → Clear site data.

16.4 Login redireciona infinitamente

Sessão não está sendo persistida. Verifique: (a) SESSION_SECRET setado; (b) cookie secure flag compatível com HTTPS do Render; (c) horário do servidor correto.

16.5 Upload de imagem falhando

Geralmente é SUPABASE_SERVICE_ROLE_KEY errada ou bucket images sem policy pública. No Supabase → Storage → images → Policies → "Public read" ativo.

16.6 Post não aparece na home

  • Confira published_at <= NOW(). Se no futuro, só aparece na hora.
  • Se tem release_date futuro, pode estar listado só em "Próximos lançamentos".

17. Checklist operacional diária

Rotina da manhã (5 minutos)

  • ☐ Abrir /admin e conferir a aba Ofertas: todas as ativas ainda estão válidas? Preço mudou? Cupom caducou?
  • ☐ Desativar ofertas que não estão mais ao vivo (toggle, sem apagar).
  • ☐ Verificar Cupons: o SECRETO aponta para o link certo do Telegram?
  • ☐ Dashboard de cliques: olhar top 5 labels das últimas 24h pra saber o que está bombando.

Ao publicar um drop

  • ☐ Criar o post com título, imagem hero, marca, modelo e release_date.
  • ☐ Subir galeria (mínimo 3 fotos) e adicionar as lojas.
  • ☐ Revisar a URL final (/post/slug) em aba anônima.
  • ☐ Compartilhar no Telegram/Instagram usando o botão "Compartilhar" da própria página.

Uma vez por semana

  • ☐ Conferir posts com release_date passado — ainda fazem sentido? Atualizar excerpt, preço.
  • ☐ Limpar ofertas inativas muito antigas (tabela do admin).
  • ☐ Rodar backup do banco (Supabase → Database → Backups).
  • ☐ Checar Clarity para ver heatmap e session recordings dos últimos dias.
